# 战斗兼容与输入边界

本次修复没有替换游戏伤害、武学或AI公式。战斗仍执行73460快照的原字节码；网页宿主提供表、时钟、随机数和输入装配。

## Lua遍历

Lua允许遍历期间清空已有字段。原宿主将当前键从Map直接删除，下一次`next`无法找到游标，导致夺天地招式筛选中止。现在保留稳定键槽作为删除游标，遍历跳过无值项；未知游标继续报错。

依据：[Lua 5.1 next](https://www.lua.org/manual/5.1/manual.html#pdf-next)、[LuaJIT表实现](https://github.com/LuaJIT/LuaJIT/blob/v2.1/src/lj_tab.c)。宿主保持自身确定顺序，不宣称已经复现游戏私有LuaJIT的完整哈希排列。回归涵盖删除当前/后续键、混合键、嵌套遍历、重插、非法游标及实际ITERN/ITERC字节码。

## 武学选项

手工角色由原获取事件对应的合法招式集合装配，互斥招式不叠加：

- 归云：`skillOptions.nei.form`为`mixed/yin/yang`，与SpecialProp一致；切换对应的一对招式。阴阳态要求十重大圆满。
- 道心：`stage`为`four-sha/five-sha/six-sha`，第五斩替换饮血祭凶，第六斩替换噬血擒心。阶段是已完成相应进程的输入假设，不会替账号完成任务。
- 羽化：`yuhuaChoices`显式选择第二、第三、摘星和天地真我的独立路线；动态属性由`specialProp`指定。
- 夺天地：手工预设包含完整上下册的隐藏招式，由原层级条件决定生效。原存档导入保留其真实取得的招式列表。

网页输入是最终面板；改变武学不会自动替用户计算装备等静态面板。原生存档应通过本地CLI导入，网页会拒绝此类输入，避免静默丢失动态状态。

## 原生存档

原`initWithConver`与getter处理装备、经脉、天赋、秘技、精进、合道和角色阵法字段。换功前先关闭同类功法，随后验证唯一激活ID。未学武学必须提供明确假设；比较时可在每臂加入同一个`learnedAssumptions`集合，固定修为上下文。见[面板工具](save-panel.md)。

时效Buff使用冻结的`nowSeconds`，全实验保持一致。复杂原角色调用可显式增加宿主`instructionBudget`，默认仍为5,000,000；这只改变允许计算的工作量，保留深度、帧数和回合保护，不修改战斗公式或跳过异常。

## 统计与适用范围

公开基准使用去标识化构造角色、固定对手和共同分散种子。每个对手分别给Wilson胜率区间与保守配对差值区间；跨对手汇总仅作描述，避免把共享种子当独立样本。失败和宿主回合截断不算败场，必须一并报告。

原始伤害、治疗含过量部分；当同一消息含内劲、罡气或其他HP效果，主伤害字段无法唯一分配全部HP损失。有效直接输出不能审计时保留null，仅另列可核对的小计，不补估算。

所有区间只反映给定模型输入下的种子波动，不涵盖模型误差、后续热更新或真实竞技场对手分布。尚未完成与同版本实机完整面板及战报逐帧对照。
