# 阵容编辑器

在网页中为我方、对手分别载入队伍预设，调整阵法、站位、武学、装备和秘技。选中角色后，右侧显示由原角色模型重算的战前面板；完成配置后再开始演武。

## 阵法与站位

我方和对手各自选择阵法及等级，互不覆盖。网页开放已核对的1–3级；3级是相关首次／每回合阵法buff的开启阈值，未据此认定游戏最高等级。较低等级的数值属性由原getter按等级比例计算。

| 阵法 | 合法原站位 | 阵眼与条件 |
| --- | --- | --- |
| 四方阵508 | 1、2、4、6、7 | 4为中心；中心效果还受其余格位在场条件影响 |
| 云垂阵515 | 3、5、6、7 | 四格分别有原位置效果 |
| 阵演万化519（万化阵） | 1–7 | 4为阵眼；缺少阵眼时关联条件效果不能激活 |
| 四时阵520 | 1、3、5、7 | 无阵眼；春夏秋冬各位置提供不同条件效果 |

七格按相对对手的方向标注：上路1前／2后，中路3前／4中／5后，下路6前／7后。两边镜像显示，同一方不能重叠占位，也不能移到该阵未开放的格位。切换阵法会采用对应推荐布局，并提示重排；之后可在合法空位中手动调整。

一般布局让央蛮及于小雪／商昊乾在前，主角、步惊云在后。万化布局的央蛮在4号中位，3号空，因此仍是该行最前的角色。易剑队采用前排主角与步惊云同行的布局；云垂阵使用明确的2+2例外：主3、步5、央6、商7。易剑四时布局让另外两人各自独占一路，商7按此例外保留。四方阵与四时阵是不同阵法，名称及格位不能互换。

阵法配置会进入原角色的`Zhen`、`ZhenLv`、`Stand`字段。战前面板只显示此阶段原getter能结算的属性；需要队友在场、回合或首次触发的效果由原战斗调度器另行处理。占了合法格位不等于所有条件buff都已激活。

## 装备、秘技与面板

角色采用公开培养蓝图，由原装备、秘技和角色对象计算属性。可编辑装备模板、基础属性、词条数值及来源，选择秘技和等级。百分比词条按百分数填写，例如`6`表示6%。高级项提供受支持的触发效果和符石编号配置。

编辑后会重算战前气血、攻击、防御、真元、内劲等属性。改变武学、装备或秘技可能影响原角色、武器类型、互斥组及槽位校验；页面会显示配置错误，修正后再演武。预设精进与合法武学分支随配置保留，更换武学时以编辑器的精进重置提示为准。

“当前有效秘技”表示原模型战前集合已纳入的项目。吸血、分摊、追加攻击、回合增益等实际触发仍取决于战斗条件。战前真元数值也不保证首招必放，出招条件与AI选择需要进入战斗后判断。

可见装备使用当前显示数值的等价重建，不能还原每件装备的完整强化历史；显示取整、隐藏培养及未观察到的玩家分支仍有误差。预设中的“满培养”以具体声明为准，不代表每个字段都已证明达到游戏上限。

## 保存与复验

- “保存方案”把当前两边配置保存到本浏览器，可在方案列表重新载入。同名保存会更新该方案。
- “导出”下载配置JSON，供备份或在另一浏览器、设备导入；导入会检查字段、站位及模型配置。
- 浏览器草稿和方案存储可能被浏览器清理，长期保留时请导出备份。导出文件反映配置，不是游戏存档。
- 固定随机种子、配置和引擎版本后复验；批量与A/B结果需要保留样本数、异常和截断信息。旧版本或不同秘技输入的结果应分别记录。

网页使用固定客户端代码和配置快照。当前PVP模型的客户端选招、原生遍历和热更新覆盖均有边界，实际服务器竞技场AI设置也未完整取得。演武结果衡量这些条件输入，不能直接当作实机竞技场胜率。

战斗结算与画面回放分别验证。内劲飘字已接入原方法；部分外观切换、依赖Spine回调的特效和交替目标动作仍可能产生回放诊断，不能据此宣称逐帧视觉还原。回放诊断不会重新生成胜负或用替代伤害覆盖战斗结果。
